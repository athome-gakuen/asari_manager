# asari_manager

Discord 上から各 Bot のデプロイ、起動状態確認、出席管理、現地イベントの参加募集を行う管理 Bot です。

## 主な機能

- `/deploy` で指定した Bot を更新して再起動
- `/checkbot` で各 Bot の systemd 状態を確認
- `/ip` でBotサーバーのグローバルIPアドレスを確認
- `/dice` で任意の面数・個数のサイコロを振る
- `/mktimes` でtimesカテゴリにフォーラムを作成
- 毎朝 8 時に「初星学園へ登校する」ボタンを投稿
- 前日の登校者上位 5 名を翌朝の投稿に表示
- 毎週日曜 20 時に登校ランキングを投稿
- `/event` で現地イベントの参加募集を作成
- `/event_list` で開催中・開催予定のイベントを一覧表示
- `/event_edit` で作成済みイベントの内容を変更
- `/event_cancel` でイベントを取り消して募集投稿を削除
- イベント募集の「参加する」「参加キャンセル」ボタンで参加者一覧を自動更新
- `/goods_offer` で写真付きのグッズ譲渡フォーラムを作成
- グッズ募集の「欲しい」「希望を取り消す」ボタンで希望者を管理
- グッズ募集の編集、譲渡先決定、完了、取り消し、期限切れ処理

## セットアップ

依存関係をインストールします。

```bash
pip install -r requirements.txt
```

`.env.example` を参考に `.env` を作成してください。

```env
DISCORD_TOKEN=
```

`DISCORD_TOKEN` には asari_manager の Discord Bot トークンを設定します。サーバー、チャンネル、カテゴリ、ロールのIDは、1階層上の `discord_ids.yml` から読み込みます。

配置例:

```text
/home/st/discord/
├── discord_ids.yml
└── asari_manager/
    ├── main.py
    └── .env
```

グッズ譲渡機能を利用する場合は、`discord_ids.yml` にgoodsカテゴリと `GOODS_CATEGORY_ID` の参照を設定してください。

```yaml
category:
  times: 1524986998316863529
  goods: 1529631760172974182

roles:
  developer: 1523478252319015052

bots:
  asari_manager:
    SERVER_ID: server_id
    STARTUP_CHANNEL_ID: channels.asari_manager_startup
    ATTENDANCE_CHANNEL_ID: channels.attendance
    DEVELOPER_ROLE_ID: roles.developer
    TIMES_CATEGORY_ID: category.times
    GOODS_CATEGORY_ID: category.goods
```

`GOODS_CATEGORY_ID` がない場合、Botは起動時に `KeyError: 'GOODS_CATEGORY_ID'` で停止します。

## Bot 設定

`bots.yml` に管理対象 Bot を登録します。

```yaml
bots:
  saki:
    path: /home/st/discord/saki
    service: saki.service
```

- `path`: 対象 Bot のリポジトリパス
- `service`: systemd service 名

| --- | --- | --- |
| `/ip` | BotサーバーのグローバルIPアドレスを表示 | 一般ユーザー |
| `/dice` | サイコロを振る | 一般ユーザー |
| `/deploy` | Botを更新して再起動 | developer |
| `/checkbot` | Botのsystemd状態を確認 | developer |
| `/mktimes` | timesカテゴリにフォーラムを作成 | 一般ユーザー |
| `/event_list` | 開催中・開催予定イベントを一覧表示 | 一般ユーザー |
| `/event` | イベント参加募集を作成 | developer |
| `/event_edit` | イベントを編集 | developer |
| `/event_cancel` | イベントを取り消し | developer |
| `/goods_list` | 受付中のグッズを一覧表示 | 一般ユーザー |
| `/goods_offer` | グッズ譲渡募集を作成 | 一般ユーザー |
| `/goods_applicants` | グッズの希望者を確認 | 一般ユーザー（自分の募集のみ） |
| `/goods_select` | グッズの譲渡先を決定 | 一般ユーザー（自分の募集のみ） |
| `/goods_edit` | グッズ譲渡募集を編集 | 一般ユーザー（自分の募集のみ） |
| `/goods_complete` | グッズの受け渡し完了を記録 | 一般ユーザー（自分の募集のみ） |
| `/goods_cancel` | グッズ譲渡募集を取り消し | 一般ユーザー（自分の募集のみ） |

### `/ip`

Botが動作しているサーバーのグローバルIPアドレスを取得して表示します。引数はありません。

```text
/ip
```

IPアドレスの取得に失敗した場合は、時間を置いて再実行してください。

### `/dice`

指定した最大値と個数でサイコロを振ります。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `max_value` | いいえ | 最大出目。1～1,000,000。未指定は6 |
| `count` | いいえ | 振る個数。1～100。未指定は1 |

通常の6面サイコロを1個振る例:

```text
/dice
```

100面サイコロを3個振る例:

```text
/dice
max_value: 100
count: 3
```

複数個を振った場合は、それぞれの出目と合計を表示します。

### `/deploy`

指定したBotをデプロイして再起動します。`bot` は必須で、`bots.yml` に登録されているBot、または `asari_manager` を選択します。

```text
/deploy
bot: saki
```

実行内容:

1. `git fetch origin`
2. `git reset --hard origin/main`
3. `.venv/bin/pip install -r requirements.txt`
4. `systemctl restart`
5. `systemctl show/status` と `journalctl` で起動状態を確認

起動できていれば `active / running` と表示します。起動に失敗している可能性がある場合は、状態と直近ログをDiscordに投稿します。

`bot: asari_manager` を指定した場合は、asari_manager自身を `origin/main` に更新して再起動します。自分自身の再起動後はコマンドへの続きの応答ができないため、起動通知チャンネルの「起動しました」で復旧を確認してください。

実行には `DEVELOPER_ROLE_ID` のロールが必要です。

### `/checkbot`

Bot の systemd 状態を確認します。

- Bot 名を指定した場合: 対象 Bot の詳細状態と直近ログを表示
- Bot 名を省略した場合: 登録済み Bot 全体の簡易状態を一覧表示

```text
/checkbot
bot: saki
```

実行には `DEVELOPER_ROLE_ID` のロールが必要です。

### `/mktimes`

`TIMES_CATEGORY_ID` で指定したカテゴリ内に、times用フォーラムを作成します。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `name` | はい | 作成するtimes名 |

```text
/mktimes
name: lilja
```

上記の例では `lilja_times` フォーラムを作成します。名前が既に `_times` で終わっている場合は、そのまま使用します。空の名前、`_times` を付けた状態で100文字を超える名前、同名のフォーラムは作成できません。

Botにチャンネル管理権限が必要です。

### イベント管理

イベントの作成、変更、取り消しには `DEVELOPER_ROLE_ID` で指定した developer ロールが必要です。通常はイベント企画チャンネルでコマンドを実行してください。

イベントを作成するとイベント番号が自動で割り当てられ、募集投稿の最下部に `イベント No.12` のように表示されます。イベントを変更または取り消すときは、この番号を指定します。

#### `/event_list` — イベントを一覧表示する

開催中・開催予定のイベントを開始日時順に最大10件表示します。引数と権限制限はありません。

```text
/event_list
```

一覧にはイベント番号、イベント名、募集状態、開始・終了日時、場所、参加人数、募集投稿へのリンクが表示されます。取り消し済みまたは終了済みのイベントは表示しません。

#### `/event` — イベントを作成する

コマンドを実行したチャンネルに、現地イベントの参加募集を投稿します。そのため、`/event` はイベント企画チャンネルで実行してください。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `title` | はい | イベント名 |
| `organizer` | はい | 企画者名 |
| `location` | はい | 開催場所 |
| `budget` | はい | 予算。例: `3000円程度` |
| `capacity` | はい | 定員。1人以上を指定 |
| `start_at` | はい | 開始日時 |
| `end_at` | はい | 終了予定日時 |
| `signup_deadline` | はい | 参加募集の締切日時 |
| `location_url` | いいえ | 地図や店舗ページなどのリンク |
| `note` | いいえ | 持ち物などの補足情報 |

日時は日本時間として、次のいずれかの形式で入力します。

```text
2026-07-20 20:00
2026/07/20 20:00
```

終了予定は開始日時より後、募集締切は開始日時以前にする必要があります。

入力例:

```text
/event
title: 打ち上げ
organizer: あさり
location: ○○駅前 △△店
budget: 3000円程度
capacity: 10
start_at: 2026-07-20 20:00
end_at: 2026-07-20 22:00
signup_deadline: 2026-07-18 23:59
location_url: https://example.com/shop
note: 現地集合
```

作成された募集投稿には次のボタンが付きます。

- `参加する`: 操作したユーザーを参加希望者一覧に追加します。
- `参加キャンセル`: 操作したユーザーを参加希望者一覧から削除します。イベント自体は取り消しません。

参加者一覧はボタン操作ごとに自動更新されます。同じユーザーの重複登録はできません。募集締切後または定員到達後は、新しく参加できません。参加済みユーザーの参加キャンセルは引き続き可能です。

#### `/event_edit` — イベントを変更する

作成済みイベントの内容を変更します。`event_id` を選び、変更したい項目だけ入力してください。入力しなかった項目と参加者一覧はそのまま保持されます。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `event_id` | はい | 変更するイベント番号 |
| `title` | いいえ | 新しいイベント名 |
| `organizer` | いいえ | 新しい企画者名 |
| `location` | いいえ | 新しい開催場所 |
| `budget` | いいえ | 新しい予算 |
| `capacity` | いいえ | 新しい定員 |
| `start_at` | いいえ | 新しい開始日時 |
| `end_at` | いいえ | 新しい終了予定日時 |
| `signup_deadline` | いいえ | 新しい募集締切日時 |
| `location_url` | いいえ | 新しい場所リンク |
| `note` | いいえ | 新しい備考 |
| `message_channel` | いいえ | 古いイベントの投稿先をBotが判別できない場合だけ指定 |

`event_id` の入力欄には、取り消されていないイベントが新しい順に候補表示されます。候補に出ない場合でも、募集投稿の下部にあるイベント番号を直接入力できます。

場所リンクまたは備考を削除したい場合は、変更する項目に `-`、`なし`、`削除` のいずれかを入力します。

日時を1項目だけ変更することもできますが、変更後も次の関係を満たす必要があります。

```text
募集締切 <= 開始日時 < 終了予定
```

定員は現在の参加希望者数より少ない人数には変更できません。

開始時刻と終了時刻を変更する例:

```text
/event_edit
event_id: 12
start_at: 2026-07-20 19:30
end_at: 2026-07-20 21:30
```

備考だけを削除する例:

```text
/event_edit
event_id: 12
note: -
```

変更に成功すると元の募集投稿が更新され、同じイベント企画チャンネルに次の情報を含む更新通知が投稿されます。

- イベント番号とイベント名
- 変更した項目
- 更新したユーザー
- 更新後の募集投稿へのリンク

#### `/event_cancel` — イベントを取り消す

イベントを取り消し、イベント企画チャンネルにある元の募集投稿を削除します。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `event_id` | はい | 取り消すイベント番号 |
| `reason` | いいえ | 取り消し理由 |
| `message_channel` | いいえ | 古いイベントの投稿先をBotが判別できない場合だけ指定 |

入力例:

```text
/event_cancel
event_id: 12
reason: 会場を確保できなかったため
```

実行に成功すると、次の処理が行われます。

1. 元のイベント募集メッセージを削除します。
2. `events.json` のイベントを取り消し済みとして保持します。
3. 同じイベント企画チャンネルへ、イベント番号、イベント名、理由、削除したユーザーを通知します。

募集投稿の削除は元に戻せません。イベント投稿が見つからない場合やBotに削除権限がない場合は取り消し処理を中止し、`events.json` の状態も変更しません。

#### 既存イベントを変更・削除する場合

現在の形式で作成したイベントは投稿先チャンネルが自動保存されるため、通常は `message_channel` の指定は不要です。

機能追加前に作成した古いイベントなど、`events.json` に投稿先チャンネルが保存されていないイベントは、次のどちらかの方法で操作してください。

- 元の募集投稿があるイベント企画チャンネルでコマンドを実行する。
- `message_channel` にイベント企画チャンネルを指定する。

#### イベント操作でエラーが出る場合

- `イベント No.X が見つかりませんでした`: 募集投稿下部の番号と入力した `event_id` が一致しているか確認してください。
- `イベント投稿が見つかりませんでした`: 元投稿が残っているか確認し、イベント企画チャンネルで再実行するか `message_channel` を指定してください。
- `developer ロールを持っている人だけ実行できます`: 操作ユーザーに `DEVELOPER_ROLE_ID` のロールが付いているか確認してください。
- 日時のエラー: 入力形式と、募集締切・開始日時・終了予定の前後関係を確認してください。
- 通知だけ失敗した場合: イベントの更新または削除は完了しています。Botがイベント企画チャンネルへ投稿できるか確認してください。

## グッズ譲渡機能

グッズ譲渡機能では、写真、グッズ名、任意の金額などを指定して譲渡募集を作成できます。コマンドを実行したチャンネルには募集を投稿せず、`GOODS_CATEGORY_ID` で指定したカテゴリ内に、グッズ専用のフォーラムチャンネルと募集投稿を自動作成します。

基本的な利用手順:

1. 譲渡者が任意のチャンネルで `/goods_offer` を実行します。
2. Botがgoodsカテゴリ内にフォーラムと写真付き募集投稿を作成します。
3. 希望者が募集投稿の「欲しい」ボタンを押します。
4. 譲渡者が `/goods_applicants` で希望者を確認します。
5. 譲渡者が `/goods_select` で譲渡先を決定します。
6. 受け渡し後、譲渡者が `/goods_complete` で完了にします。

操作権限:

| 操作 | 利用できるユーザー |
| --- | --- |
| 募集作成、募集一覧、希望登録・取り消し | サーバー内の一般ユーザー |
| 希望者確認、編集、譲渡先決定、完了、募集取り消し | サーバー内の一般ユーザー（自分が作成した募集のみ） |

グッズ譲渡機能の利用にdeveloperロールは必要ありません。ただし、他のユーザーが作成した募集の希望者確認、編集、譲渡先決定、完了、取り消しはできません。

### 作成されるフォーラムと募集投稿

グッズごとに、次のようなフォーラムチャンネルを1つ作成します。

```text
goodsカテゴリ
├── goods-0001-アクリルスタンド
├── goods-0002-缶バッジ
└── goods-0003-ライブタオル
```

フォーラム内には募集投稿を1件作成し、以下を表示します。

- グッズの写真
- グッズ名とグッズ番号
- 譲渡者
- 金額
- 個数
- 状態、説明、募集期限
- 現在の希望者数
- 「欲しい」「希望を取り消す」ボタン

グッズの状態に応じて、フォーラム名の先頭が変わります。

| 状態 | フォーラム名の例 |
| --- | --- |
| 受付中 | `goods-0001-アクリルスタンド` |
| 譲渡先決定 | `reserved-goods-0001-アクリルスタンド` |
| 譲渡完了 | `closed-goods-0001-アクリルスタンド` |
| 取り消し | `cancelled-goods-0001-アクリルスタンド` |
| 期限切れ | `expired-goods-0001-アクリルスタンド` |

### `/goods_offer` — グッズ譲渡募集を作成する

サーバー内のどのチャンネルからでも実行できます。実行した本人には、作成された募集投稿へのリンクが非公開で返されます。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `name` | はい | グッズ名。1～200文字 |
| `photo` | はい | グッズの画像ファイル |
| `price` | いいえ | 金額。0～100,000,000円。未指定または0は「無料」 |
| `condition` | いいえ | 開封状況、傷、汚れなど。1000文字以内 |
| `quantity` | いいえ | 個数。1～1000個。未指定は1個 |
| `deadline` | いいえ | 募集期限。`YYYY-MM-DD HH:MM` または `YYYY/MM/DD HH:MM` |
| `description` | いいえ | 説明や注意事項。1000文字以内 |

入力例:

```text
/goods_offer
name: 学園アイドルマスター アクリルスタンド
photo: goods.jpg
price: 1000
condition: 開封済み・目立つ傷なし
quantity: 1
deadline: 2026-08-01 23:59
description: イベント会場で購入したものです
```

作成に成功すると、次の処理が行われます。

1. `goods.json` からグッズ番号を発行します。
2. goodsカテゴリ内に専用フォーラムを作成します。
3. フォーラム内に写真付き募集投稿を作成します。
4. 投稿、フォーラム、画像などのIDを `goods.json` に保存します。

写真以外のファイルを指定した場合、過去の日時を募集期限にした場合、Botにチャンネル管理・投稿・ファイル添付権限がない場合は作成できません。募集投稿の作成に失敗した場合、途中まで作成したフォーラムはBotが削除します。

### 「欲しい」「希望を取り消す」ボタン

募集投稿の「欲しい」ボタンを押すと、譲渡希望者として登録されます。登録結果は本人だけに表示され、公開Embedでは希望者の人数のみ更新されます。

- 同じユーザーは同じグッズに重複登録できません。
- 譲渡者本人は、自分のグッズに希望を出せません。
- 「希望を取り消す」で自分の希望を取り消せます。
- 譲渡先決定後、完了後、取り消し後、期限切れ後はボタンを利用できません。
- Bot再起動後もボタンは引き続き利用できます。

フォーラム投稿へのコメントは質問や相談に利用できますが、コメントしただけでは譲渡希望として登録されません。譲渡を希望する場合は必ず「欲しい」ボタンを押してください。

### `/goods_list` — 受付中のグッズを一覧表示する

現在受付中のグッズを、新しいものから最大10件表示します。引数はありません。

```text
/goods_list
```

一覧にはグッズ名、番号、金額、希望者数、募集期限、募集投稿へのリンクが表示されます。譲渡先決定済み、完了、取り消し、期限切れのグッズは表示しません。

### `/goods_applicants` — 希望者を確認する

募集に登録されている希望者を、登録順に非公開で表示します。一般ユーザーが、自分で作成した募集に対して実行できます。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `goods_id` | いいえ | 対象のグッズ番号。募集投稿内で実行する場合は省略可能 |

募集投稿内で実行する例:

```text
/goods_applicants
```

別のチャンネルから実行する例:

```text
/goods_applicants
goods_id: 12
```

### `/goods_select` — 譲渡先を決定する

「欲しい」ボタンを押した希望者の中から、譲渡先を1人決定します。一般ユーザーが、自分で作成した募集に対して実行できます。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `recipient` | はい | 譲渡先に決定するDiscordメンバー |
| `goods_id` | いいえ | 対象のグッズ番号。募集投稿内で実行する場合は省略可能 |

入力例:

```text
/goods_select
recipient: @ユーザー
goods_id: 12
```

指定したメンバーが希望者として登録されていない場合は決定できません。決定に成功すると、募集状態が「譲渡先決定」に変わり、希望ボタンが無効化され、フォーラム名と募集Embedが更新されます。募集投稿には譲渡先をメンションした通知を投稿します。

受け渡し場所、住所、振込先などはBotに保存せず、当事者間で相談してください。

### `/goods_edit` — 募集内容を編集する

受付中のグッズ募集を編集します。一般ユーザーが、自分で作成した募集に対して実行できます。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `goods_id` | いいえ | 対象のグッズ番号。募集投稿内で実行する場合は省略可能 |
| `name` | いいえ | 新しいグッズ名 |
| `photo` | いいえ | 新しい写真。指定すると以前の写真を置き換える |
| `price` | いいえ | 新しい金額。0は無料 |
| `condition` | いいえ | 新しい状態。削除する場合は `-` |
| `quantity` | いいえ | 新しい個数 |
| `deadline` | いいえ | 新しい募集期限。削除する場合は `-` |
| `description` | いいえ | 新しい説明。削除する場合は `-` |

金額と写真を変更する例:

```text
/goods_edit
goods_id: 12
price: 500
photo: new-goods.jpg
```

説明と期限を削除する例:

```text
/goods_edit
goods_id: 12
description: -
deadline: -
```

変更する項目だけを指定してください。グッズ名を変更した場合はフォーラム名も更新されます。譲渡先決定後、完了後、取り消し後、期限切れ後は編集できません。

### `/goods_complete` — 受け渡し完了にする

譲渡先決定済みのグッズを「譲渡完了」にします。一般ユーザーが、自分で作成した募集に対して実行できます。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `goods_id` | いいえ | 対象のグッズ番号。募集投稿内で実行する場合は省略可能 |

```text
/goods_complete
goods_id: 12
```

完了にすると、募集Embedとフォーラム名を更新し、完了メッセージを投稿したあと、募集投稿をロックしてアーカイブします。先に `/goods_select` で譲渡先を決定していないグッズは完了にできません。

### `/goods_cancel` — 募集を取り消す

受付中または譲渡先決定済みの募集を取り消します。一般ユーザーが、自分で作成した募集に対して実行できます。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `goods_id` | いいえ | 対象のグッズ番号。募集投稿内で実行する場合は省略可能 |
| `reason` | いいえ | 取り消し理由。1000文字以内 |

```text
/goods_cancel
goods_id: 12
reason: 譲渡を取りやめることになったため
```

取り消すと、募集Embedとフォーラム名を更新し、理由を投稿したあと、募集投稿をロックしてアーカイブします。完了済み、取り消し済み、期限切れの募集は操作できません。

### 募集期限と自動終了

`deadline` を指定した募集は、Botが1分ごとに期限を確認します。期限を過ぎると次の処理を自動で行います。

1. 状態を「期限切れ」に変更します。
2. 「欲しい」「希望を取り消す」ボタンを無効化します。
3. フォーラム名を `expired-goods-...` に変更します。
4. 期限切れメッセージを投稿します。
5. 募集投稿をロックしてアーカイブします。

### グッズ操作でエラーが出る場合

- `GOODS_CATEGORY_ID のカテゴリが見つかりませんでした`: `discord_ids.yml` の `GOODS_CATEGORY_ID` とDiscord上のカテゴリIDを確認してください。
- `対象のグッズが見つかりません`: 募集投稿内で実行するか、Embed下部のグッズ番号を `goods_id` に指定してください。
- `この募集を作成した本人だけです`: コマンド実行者が募集作成者本人か確認してください。
- フォーラム作成に失敗する: Botにチャンネル管理、スレッド作成、メッセージ送信、ファイル添付の権限があるか確認してください。
- 募集メッセージを更新できない: フォーラムや募集投稿が手動削除されていないか確認してください。
- 日時のエラー: 入力形式が `YYYY-MM-DD HH:MM` で、現在より後の日時になっているか確認してください。

## 登校機能

毎朝 8 時に `ATTENDANCE_CHANNEL_ID` へ以下の内容を投稿します。

- 朝のメッセージ
- 前日の登校者上位 5 名
- `初星学園へ登校する` ボタン

ユーザーがボタンを押すと、その日の登校者として記録され、本人だけに以下の起動リンクが表示されます。

- iPhone版（App Store）
- Android版（Google Play）
- PC版（DMM GAMES）

同じユーザーが同じ日に複数回押しても、記録は 1 回だけです。記録済みの場合も起動リンクは再表示されます。

毎週日曜 20 時には、その週の登校ランキングを投稿します。

## 保存ファイル

Bot は以下の JSON ファイルにデータを保存します。

- `attendance.json`: 登校記録、投稿済み日付、週間ランキング投稿履歴
- `events.json`: イベント情報、参加者一覧、イベント番号、投稿先チャンネル、更新・取り消し状態
- `goods.json`: グッズ情報、写真URL、希望者一覧、グッズ番号、フォーラム・投稿ID、譲渡状態

これらのファイルは自動生成されます。

## sudoers 設定

`/deploy` と `/checkbot` をDiscordから実行するには、Bot実行ユーザーがpasswordなしで `systemctl` と `journalctl` を実行できる必要があります。

例:

```sudoers
st ALL=NOPASSWD: /bin/systemctl restart saki.service
st ALL=NOPASSWD: /bin/systemctl is-active saki.service
st ALL=NOPASSWD: /bin/systemctl show saki.service *
st ALL=NOPASSWD: /bin/systemctl status saki.service --no-pager
st ALL=NOPASSWD: /bin/journalctl -u saki.service -n 40 --no-pager

st ALL=NOPASSWD: /bin/systemctl restart asari_manager.service
```

環境によって `systemctl` や `journalctl` のパスが異なる場合があります。サーバーで以下を確認し、コード側の `SYSTEMCTL` / `JOURNALCTL` と sudoers のパスを合わせてください。

```bash
which systemctl
which journalctl
```

## 起動

```bash
python main.py
```

systemd で運用する場合は、`asari_manager.service` を作成して常駐させてください。
